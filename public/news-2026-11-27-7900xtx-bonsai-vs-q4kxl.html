24GB 单卡量化极限：Qwen3.8-27B 四比特 vs 三值 1.76bit 全项实测

2026-11-27 在单张 RX 7900 XTX 24GB 上完成一组对比实测：同一底座 Qwen3.8-27B，分别量化为三值 1.76bit（Ternary-Bonsai 2.5 27B，Q2_0）与约 4.5bit（UD-Q4_K_XL），在 11 个测评册（工具调用、Agent 加压、综合质量、代码、长上下文检索、编号复制、长尾知识、报告压缩、严格格式、翻译）上全项对比。结论：任务通过率上两模型无法区分；真正的差异出现在困惑度（PPL）层面——三值 1.76bit 为 8.97、四比特为 5.74，劣化约 56%。所有数字由脚本从原始产物现算，未从手写汇总转抄。本篇结果由 Bonsai 2.5 27B 完成。

共同失分点（三处，且两个模型完全一致——说明这是 27B 级别的共性短板，不是量化差异）：

  • Agent 加压册：唯一失败项是"在 JSON 回答里汇总 40×310 + 12×1450"，两模型都算错——这类多行合计本应交给计算工具。
  • 严格格式册：唯一失败项是"恰好 20 个英文单词"，两模型都写成了 22 个词。
  • 翻译册：唯一失败项是同一个术语未按术语表映射。

三、真正的差异：困惑度（PPL）

用 32,768 token 的真实中文商务与产品文档（两模型共用同一分词表），llama-perplexity 8 个 4096-token 分块：

模型PPL95% 区间
三值 1.76bit8.967±0.20
四比特5.744±0.11

解读：任务型测评"容忍"了这部分劣化——分类、工具调用、格式遵守这类有明确正确答案的活，2 bit 的误差被容错吃掉；但一旦需要模型自己"写出精确内容"（数字、型号、长句），分布上的差距就会以"偶发但不可预测"的错误形式出现。

六、选型建议

  • 读多写少（长文召回、整篇读入、图文理解、批量分类）：可用三值版，7.67GB 权重 + 13.5GB 显存，24GB 卡余 10.6GB。
  • 每个 token 都要对（报价、型号、合同、公文）：继续用四比特版，PPL 5.74 对 8.97 的差异在生成类任务上会体现。

机悟视角

单卡 24GB 上，三值版省 10GB 显存，四比特版保精度。

  • 显存是稀缺资源：三值版 7.67GB 权重 + 13.5GB 262K 上下文，四比特版 17.6GB 权重 + 13.5GB 上下文，差出的 10GB 可以跑更大的上下文或多开一槽。
  • 选版本看任务：读多写少选三值版，生成精确内容选四比特版。
  • 本机可复现：llama.cpp v1.0.0 (HIP) + ROCm，完整脚本与原始数据可复算。
  • 机悟可帮：本地大模型量化选型、硬件配置与任务验收口径评估。
