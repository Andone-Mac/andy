OpenAI GPT-Live-1.1 进入 API：全双工语音，待机每分钟 0.02 美元

实时语音 API 有了一个「会安静下来」的新选项：OpenAI 官方社区 11 月 20 日宣布，GPT-Live-1.1 进入 API（模型 ID gpt-live-1.1；系统卡 Change log 标注 11 月 19 日）。这个模型自 10 月 15 日起就在 ChatGPT Plus/Pro 里支撑语音对话，特点是「边说边听」——它说话时仍在听你，复杂任务可以委派给你选的后端模型而不打断对话流。更实用的是新增的 standby 待机：静默 5–60 秒后暂停推理但保持连接，待机每分钟 $0.02，只有活跃价 $0.05 的四成。

一、全双工加后端委派：对话不被任务打断

官方公告口径：GPT-Live-1.1 可以边说边听（listen while it speaks），并把复杂工作流委派给开发者选定的后端模型，不打断对话流；官方称多语言口音一致性、字母数字辨识、指令遵循与任务可靠性提升。系统卡（deploymentsafety.openai.com/gpt-live-1-1）Change log 11 月 19 日增补 API 语音安全评测；1.1 与 1.1 Quip 面向 ChatGPT、Codex、Dots，1.1 API 面向实时对话，全双工。

二、standby 待机：安静时段按四折计费

状态费率口径
活跃$0.05/分钟官方公告
待机$0.02/分钟官方公告
待机触发静默 5–60 秒可配官方公告
后端模型与工具另行计费官方公告

standby 对 GPT-Live-1 与 1.1 通用：静默超时（5–60 秒可配）后暂停推理，WebRTC 连接保持，用户再开口即恢复。算一笔账（本刊计算）：一通 10 分钟的客服通话，若 4 分钟活跃、6 分钟待机，费用 $0.32，比全程活跃的 $0.50 省 36%；待机单价比活跃低 60%。注意「后端模型和工具使用另行计费」——委派给后端模型跑复杂任务时，语音层省的钱可能在后端层花回去，月账要两层一起算。

  • 音色：社区帖列出 38 个 voice ID（含新增 calandria、compas、destello、halo、hornero、luciernaga、pearl 等）。
  • 速率限制：官方模型页未公布 tier 速率限制（社区帖指出），接入前以控制台与文档为准。
  • 官方 changelog 页面本刊抓取超时，上线日以系统卡 11 月 19 日与社区公告 11 月 20 日双源为准。

三、对政企的意义：语音客服的成本结构变了

实时语音客服过去的成本痛点是「沉默也在烧钱」：连接保持期间模型持续推理计费。standby 把沉默时段降到四折，对平均通话时长长、沉默占比高的场景（售后、陪伴、导览）是结构性利好。选型时把三个数放进测算表：活跃与待机单价、平均沉默占比、后端委派频率；再对照国内方案（如火山 SeedRealtime 1.0 按通话时长计费，本站同批发布）做总账比较。

机悟建议：语音 API 月账，两层一起算

语音层省的钱，可能在后端层花回去

  • 语音层 $0.05/$0.02 每分钟，后端模型与工具另计，月账两层相加。
  • 沉默占比高的场景先估 standby 收益（本刊示例省 36%）。
  • tier 速率限制官方未公布，压测后再定并发。
