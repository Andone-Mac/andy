阿里把「Agent 执行底座」开源了：Qwen Code 1.0 Preview 融合 Qoder 的 Harness，Apache-2.0 可嵌入自己的产品

11 月 11 日，阿里官宣 Qwen Code 1.0：把 Qoder 里打磨的 Agent 执行基座（Harness）并进开源项目 Qwen Code，以 Apache-2.0 随 1.0 Preview 开放。这不是一次模型发布——被打开的是「模型接工具、接执行」的那一层，开发者可以把它嵌进自己的产品，企业不必再从空白页开始搭编程智能体。

一、开源的到底是什么

Harness 直译「马具」，在智能体语境里指衔接模型、工具与执行过程的运行层：会话生命周期、执行状态、消息历史、权限边界都在这一层。阿里把 Qoder 中打磨的这层能力融入 Qwen Code，官方描述其架构路径是：从进程内的内存事件总线起步，沿统一事件模型向分布式演进，把接入、调度与执行分层扩展，通过「手脑分离」让推理编排与工具执行独立管理——从「一个进程、多个会话」走向「多个节点、更多会话」，同时保留既有入口与返回方式。

  • 处理单元按需接入：推理、记忆与工具能力围绕事件挂载，减少对主执行流程的侵入。
  • 模型接入集中管控：模型服务经统一入口接入，集中管理配置、访问授权与调用记录——「减少重复对接与分散维护」。
  • 沙箱按权限边界复用：在相同配置与权限边界内分配和复用，减少重复初始化与空闲占用，官方称有助于降低运行成本。
  • MCP 统一治理：工具协议（Model Context Protocol）的配置、授权与连接一处管理，减少分散维护。

二、「1.0」的三个边界

容易被读过的三点：其一，这不是模型发布，而是开源 Agent 运行时的版本节点，模型访问、账号可用性与 API 费用依所选供应方；其二，「1.0」这个称呼目前主要对应 GitHub Releases 的 v1.0.0-preview 预发布标签与官方产品页——第三方核对显示 npm 渠道 latest 标签仍是 0.27 系列，「1.0 Preview」挂在独立分支上（v1.0.0-preview 与 main 在 Git 历史里没有共同祖先，两条发布线并行）；其三，官方明确 Preview 期间接口、配置和行为可变，阿里未公布稳定 1.0 的时间表，也未发布基准成绩，开源内核与 Qoder 产品内运行版本的吻合度同样未披露。

  • 别机械合并两条线：沙丘社区提示——不要把 0.27.x 的全部既有功能和本轮随后合入的 event-bus 接口，写成 1.0 已具备的能力。
  • 入口齐备：官方发布说明确认可用 Qwen 与 Qoder 账号、多模型供应方及自定义兼容端点，提供 macOS、Linux、Windows 原生安装包（无须另装 Node.js），并支持会话续接与非交互执行——最后这条意味着它从第一天就是按「可进自动化流水线」设计的。

三、为什么这比又一个编程助手值得记

编程智能体产品过去两年一拨接一拨，多数把执行层焊死在自己产品里。这次的不同在于：阿里把「跑得久、管得住」的那层拆出来开源了——统一事件、权限边界、沙箱复用、调用留痕，恰好是企业自建智能体时最难自研、也最容易被审计追问的四件事。官方产品页还有一条产业信号：Qwen Code 的新内核参与 Qwen 模型的联合训练，以真实任务轨迹为依据，让训练、执行策略与评测相互反馈——执行底座不再只是「用模型」，开始反过来「教模型」。

对做私有化智能体的团队，路径也因此清楚了半截：底座开源（Apache-2.0，商用许可宽松）+ 模型经统一入口接自有推理服务 + 工具与沙箱留在自己边界内——这比从零写一套 Agent Loop，或把业务数据交给闭源 SaaS，都更接近合规舒适区。产品页同时列了 Agent Teams（多智能体分工协作）、CodeMode（用脚本组织多个工具调用）、Goal（围绕目标持续执行、到上限或阻塞即停）等运行方式。

机悟建议：拿开源 Harness 搭自有智能体的三步

给在「自研 vs 借用 vs 买 SaaS」之间犹豫的团队（2026-11-12）

  • 先分清两条版本线再立项：稳定线跑生产试点，Preview 线做内部工具与评估；官方说了接口会变，别把试点直接押在 Preview 上。
  • 统一入口是合规抓手：模型配置、授权、调用记录集中管理这一条，内网部署同样成立——先把入口收拢，再谈接入几个模型。
  • 内核开源不等于模型免费：Apache-2.0 只管代码层；接入的模型供应方许可与费用各自另算。
  • 评估口径早定：同一任务集上量「完成率 + 返工率 + 每任务成本」，Harness 换内核、模型换档位，都拿这把尺复测。
