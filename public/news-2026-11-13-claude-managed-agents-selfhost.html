2026-11-13智能体 · 私有化部署

闭源大厂也把「内网运行」做成产品：Claude 智能体自托管版进私测，会话记录留在企业自己的机房

11 月 12 日，Anthropic 官方发文：Self-hosted Claude Managed Agents 进入私有测试。此前「智能体跑在企业自己的边界内」更多是中国私有化部署市场的默认需求，现在美国头部闭源厂商把它做进了产品目录：智能体的执行框架、沙箱、会话历史都可以留在企业自己的云或机房里，模型请求发去哪里由企业自己选，每一步操作留完整审计记录。对关注「数据不出域」的买家，这份公告值得逐条读。

一、公告里能自托管什么

  • 三样东西自己留：agent harness（执行框架）、运行沙箱（agent 用 shell 和文件工具的地方）、会话历史。部署粒度三档可选：Anthropic 全托管、只自建沙箱、整个服务自建。
  • 模型请求去向自选：可以直连 Anthropic，也可以走 Amazon Bedrock、Google 的 Agent Platform、Microsoft Foundry，或者企业自己的网关。官方强调：这与「在哪里执行工具」是两个独立的开关。
  • ZDR 同样适用：组织若与 Anthropic 签有零数据保留（zero data retention）协议，自托管场景下发给 Claude 的请求按普通 Messages API 调用同等对待。

二、审计与权限：设计原则三条

官方把产品原则概括为「大脑与双手分离」（模型推理与工具执行拆开）、白名单授权、全程留痕：

  • 白名单：每个智能体有一张允许触碰的外部系统清单——官方举的例子是「修构建失败」的智能体，清单可能只有代码托管与包仓库两项；企业自建沙箱时，这套限制由自己的防火墙兜底。
  • 全程留痕：每一步操作（调用过哪些工具、返回了什么）都进会话记录，可经 OpenTelemetry 导出到企业现有监控体系，与其余系统日志放在一起审查。
  • 三档部署共用同一套原则：无论是 Anthropic 托管一切、只托管沙箱、还是整服务自建，审计与白名单逻辑不变。

三、获取方式与同日动作

这是私有测试（private beta）：官方入口是「联系你的 Anthropic 客户团队申请」，同时发布了公开文档。没有自助开通，也没有开放时间表的承诺。同日，Anthropic 还发布了 Claude for Manufacturing——面向制造业的插件，含 17 项技能与 4 类连接器，主打从企业已有系统里起草报价单、质量报告与供应商询价，可见其企业线正在同一天多线推进。

四、对照国内私有化：这套形态在讲什么

  • 「自托管」的重心在运行环境，不在模型：这套方案允许「手在内网、脑在云端」——工具执行与数据留在企业边界，推理请求仍可能外发（去向自选）。国内政企常见的合规要求通常是推理也不出域，两者不是同一道题的答案。
  • 但方向一致：闭源大厂开始把「执行层驻场 + 审计导出 + 白名单」做成标准件，等于给「智能体进企业内网」这条路线背书——这正是国内一体机与私有化部署服务商一直在交付的形态，合规口径还可以做得更严。
  • 接入前先看清门槛：需要 Anthropic 客户团队通道，国内多数团队没有现成采购路径；审计字段与企业现有监控（日志、工单、SIEM）的兼容性也需要先验证。

机悟建议

看海外自托管公告，抄它的检查清单

  • 先列「双手清单」：给每个要上岗的智能体写明白名单——它允许碰哪些系统，碰不到的默认拒绝。
  • 再定「大脑去向」：推理请求发云端还是留内网，按数据分级定；涉密与敏感业务建议整链路不出域，国内私有化栈可满足。
  • 审计先接进来：选智能体平台时，把「全量执行记录能否导出到你现有监控系统」写成硬性验收项。
  • 别把私测当现货：公告与可采购之间通常隔着数周乃至数月，先把同形态的本地方案跑起来更实在。
