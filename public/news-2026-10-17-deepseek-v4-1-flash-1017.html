DeepSeek V4.1-Flash-1017 发布：DeepSWE 77.0、MIT 权重次日上线，Search/Fetch API 同期开放

10-17，DeepSeek 把 V4.1-Flash-1017 推到网页端、App 与 API，官方称之为性能与费用同时改善的「帕累托改进」：DeepSWE v1.1 77.0（前代 74.2）、Terminal-Bench 4.0 42.3（31.2），同时缩短任务运行时间与输出长度。权重于同日以 MIT 许可在 Hugging Face 发布，官方自研搜索引擎的 Search/Fetch API 也一起对外开放——对本地化部署而言，这是「权重宽松 + 成本可算」的组合。

先看官方给的两组数：分数在涨，时间在降

按 DeepSeek 官方新闻稿（10-17，标题《Wish-Driven Programming：许愿式编程一键成真》），V4.1-Flash-1017 与其上一版 V4.1-Flash 的对比中，Agent 与编码类基准普遍上移，且官方明确把「缩短任务运行时间与输出长度」与「提升基准」放在同一句里表述，称在多个 Harness 下达到新的性能—费用帕累托最优。

  • DeepSWE v1.1：77.0（前代 74.2），测试框架 mini-swe-v2；
  • Terminal-Bench 4.0：42.3（前代 31.2），使用 Claude Code 框架测试；
  • ProgramBench：29.1（20.3）；NL2Repo-Bench：68.2（65.4）；
  • Automation-Bench V1.0.6：60.5（54.8）；Agents' Last Exam：35.4（31.8）；
  • Apex Bench v1.1：72.1（64.6）；HLE（无工具）：42.6（36.8，仅测文本子集）。

需要说清口径：以上均为厂商自测，测试框架与取值条件写在官方脚注里，第三方复测尚未出现。对采购方，这一组数字的意义不在于「谁第一」，而在于同一模型版本内的自比——同一套框架下前代与当代的差值，比跨厂商的榜单排名更接近「换版本能带来多少实际收益」。

这次改的是「单位任务成本」，不只是分数

官方把这版的技术路线归结为基于自反馈的强化学习（RL）训练：用模型自身的置信度与自生成批评作为训练信号，重点提升了「从零开始构建完整项目」的能力，官方演示包括 3D 建模、网页小游戏、基于 Godot 引擎的项目复刻等。这类任务的共同点是交互轮次多、工具调用密集——这正是 Agent 场景里成本被放大的地方。

与之一致的是工程侧的动作：官方点名针对 DeepSeek Harness、腾讯 CodeBuddy、WorkBuddy 等框架做了专项优化，并要求升级到 DeepSeek Harness 0.2.1-rc.1 及以上以获得适配。对政企使用者，这条信息比基准分更实用：同一张卡、同一套内网环境，换版本能否缩短任务时长、减少输出 token，直接决定单次业务处理的成本。

权重 MIT、次日上线：许可条款比分数更影响选型

权重侧的事实可以独立核实：Hugging Face 上 deepseek-ai/DeepSeek-V4.1-Flash-1017 仓库于 2026-10-17 创建，许可证标签为 MIT，精度为 FP8，仓库非门控（gated: false）。上线一天内下载量约 1.0 万次、收藏 1177。

MIT 是这轮发布里最容易被低估的一点。企业做本地化部署时，真正卡住的往往不是显存，而是许可：能不能商用、能不能改、能不能把权重放进内网镜像、二次分发给分支机构和集成商要不要额外授权。MIT 这类宽松许可把这些问题的答案提前给了出来，法务评估的路径因此短很多。反过来，许可收紧的模型即便分数更高，也可能在采购流程里被一票否决。

Search / Fetch API 同期开放：检索也开始按次计价

同日，DeepSeek 把长期支撑其网页端与 API 端搜索能力的自研搜索引擎对外开放：POST /v1/tools/search 返回结构化结果（含长摘要、发布时间与权威度评级），POST /v1/tools/fetch 把指定网页抓成 Markdown。计费口径是按成功请求计：每千次 5 元，失败、空结果与超时不收费，Search 与 Fetch 各限每账号 5 QPS；2026-11-01 前通过 Harness、Claude Code、Codex 的服务端工具调用不计费。

对做 RAG 与 Agent 的团队，这意味着检索成本第一次可以被写成一行预算：一次查询约 0.005 元，一万次约 50 元。相比自建爬虫加向量库的运维投入，按次计价在小规模阶段更划算；规模上来之后，是否继续外采则取决于数据是否允许出域——这一条对政企往往是决定性的。

对政企的含义：许可、成本、可离线，三条一起看

把这次发布拆成三件事，正好对应本地化部署评估表上的三栏：许可（MIT，商用与二次分发路径清晰）、成本（官方口径是性能与费用同时改善，实际收益需在自己的任务集上复测）、可离线（FP8 权重公开，可进内网镜像）。三者同时成立时，模型才真正具备「内网可用」的条件，缺一项都会在验收阶段暴露。

需要提醒的是：官方基准不覆盖企业自有任务，换版本前应在自己的 20–50 条真实任务上做 A/B，比较的是任务完成率、平均轮次与输出 token，而不是榜单分数。这一步做与不做，决定了「升级」是成本优化还是新的不稳定来源。

机悟的建议：换版本之前，先算清「单位任务成本」

分数涨了不等于账单降了，要按自己任务集复测。

  • 许可先过关：确认权重许可允许商用与内网分发（本版为 MIT），把许可条款写进选型评分表，避免验收阶段返工；
  • 自建任务集复测：用 20–50 条真实业务任务做新旧版本 A/B，记录完成率、平均交互轮次与输出 token，三项一起看；
  • 版本与框架对齐：官方优化绑定 Harness/CodeBuddy/WorkBuddy 等框架及 0.2.1-rc.1 以上版本，内网部署前先确认框架版本匹配；
  • 检索成本单列：外采按次计价的搜索/抓取接口要单独列出预算，涉及数据出域的场景优先内网检索方案。
