GLM-5.3-Highspeed 被曝实测 490 tokens/s：模型竞争开始比「每秒能出多少字」

据量子位 2026-10-12 报道，有网友称在 Zcode 3.15.1 中体验到智谱的新模型 GLM-5.3-Highspeed，晒出的输出速度达 490 tokens/s；该名称此前已被 Pi 的模型目录收录（上下文窗口 100 万 token、单次最大生成 131,072 token，low/high/max 三档思考强度，与 GLM-5.3 普通版一致）。作为对照：上月的 GLM-5.3-FlashX 上限约 200 t/s，Artificial Analysis 测得 GLM-5.3-Flash 在 Z.ai API 上约 60 t/s，今年 5 月的 GLM-5.1-Highspeed 为 400 t/s。需要强调：官方尚未确认该型号与速度，模型仍在随机灰度中。

四个速度数字，放一起看

  • 490 tokens/s——网友在 Zcode 3.15.1 里晒出的 GLM-5.3-Highspeed 实测值（订阅用户随机灰度，未经官方确认）。按同样速度线性外推，输出 1 万 token 的生成阶段约需 20 秒。
  • 400 tokens/s——2026 年 5 月发布的 GLM-5.1-Highspeed，当时被称为刷新了厂商 API 的速度上限。
  • 200 tokens/s——上月的 GLM-5.3-FlashX 最高速度。
  • 约 60 tokens/s——Artificial Analysis 对 GLM-5.3-Flash 在 Z.ai API 上的输出速度测值。

速度为什么变得值钱

过去两年选型看的是「答得对不对」，现在多了一栏「多快能答完」。原因很实际：当模型从「聊天」走向「干活」——长文档梳理、批量材料处理、多轮工具调用——单次生成动辄几千到上万 token，吞吐直接决定这件事能不能嵌进日常工作流。同样的任务，60 t/s 和 400 t/s 的差别，是「等一会儿」和「等一上午」的差别。

对本地化部署，还有一层：内网机器的吞吐决定了能同时供几个人用。显存与批处理策略既定时，推理速度就是并发能力——这也是很多单位最后发现「买得起卡，但用起来卡」的地方。

冷静的一半：第一，这是单点灰度实测，同一型号在不同套餐、不同负载下差异很大，也不排除与社区讨论的其它匿名型号有关；第二，同名的「高速版」通常意味着在某些环节做了取舍（思考预算、蒸馏、缓存策略），速度上去了，复杂任务的正确率未必同步；第三，速度只是选型的一栏，许可证与能否本地部署仍是硬门槛。以官方发布与您自己机器上的实测为准。

机悟的建议：把「每秒 token」当成选型表里的一栏，而不是全部

速度决定能不能用起来，效果决定值不值得用；两个都得在您自己的硬件上量。

  • 按任务测吞吐：用您真实的输入长度与输出长度测，长输入更要看首字时延（预填充）——它往往才是体感慢的来源。
  • 把并发一起算：问清楚「这一速度下能同时服务几个人」，再折算成硬件配置，别只看单人跑分。
  • 先过许可证与本地部署这道门槛：能商用、能进内网的型号才有讨论速度的意义；灰度期信息以官方发布为准。
