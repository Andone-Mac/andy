AI 编程助手把密码写进了公开仓库：31,088 个密钥，检出时 17% 还能用

这条不是「某个模型变笨了」，而是「给 agent 的便利开关，会把密钥写进它自己管理的文件」。对企业更能对上号的是后半段：会话记录、共享配置、部署笔记同样带着凭据，而常规密钥扫描器有一大批根本认不出来。

一、两套口径，两个数——都对

同一件事出现了两组差距 20 多倍的数字，读的时候容易以为有一方错了。实际是两个不同的问题：Apiiro 问「今天还暴露着什么」，GitGuardian 问「曾经被推送过什么」。

来源与口径扫了什么结果
Apiiro（11-05 报告，11-09 媒体披露）默认分支当前副本快照，保守过滤，未测试凭据是否有效103,617 个仓库、104,185 份设置文件；1,122 份含真实密钥（1,379 个不同密钥）；再合并 Git 历史、共享设置与会话记录后为 2,539 个、1,994 个仓库、63 家组织
GitGuardian（11-09 研究博客）每次公开提交被推送时的内容，含后来被删除或 force-push 掉的版本；对可验证项做只读有效性检查23,276 个仓库、31,088 个不同密钥；5,343 个（17%）在检出时仍然有效；公开 Docker Hub 镜像另涉 613 个密钥、99 个有效

GitGuardian 自己的说法是「两个数字都对」：第一个回答今天暴露面有多大，第二个才是那些本该被轮换掉的凭据有多少。做处置时两个都要用——前者定优先级，后者定轮换范围。

二、机理：一条被记住的命令

Claude Code 在执行多数 shell 命令前会询问授权。用户选「是，且不再询问」后，规则被写进项目目录下的 .claude/settings.local.json；如果规则记的是命令原文而不是通配模式，命令里夹带的密码、令牌、密钥就一起落了盘。按设计这个文件应被开发者全局 .gitignore 排除，但那条排除写在开发者本机配置里、不写进仓库自身的 .gitignore——项目被克隆到另一台机器、或者普通文件夹后来才被初始化为 Git 仓库时，它就会被提交上去。

Apiiro 还观察到更麻烦的一层：在 1,105 个含密钥的仓库里，有 539 个的提交里 Claude 是共同作者，即文件是随 agent 的提交一起进去的。原仓库删掉文件也不够——已经 fork 的副本、以及历史提交里的内容仍在。

三、泄露的到底是什么

类型数量（Apiiro 快照口径）
数据库密码379
公开服务器 SSH 登录（含 root）43
AWS 密钥23
GitHub / GitLab / npm 令牌42
受影响组织63（从学生团队到成熟供应商）

样本里还有数据库服务商自身的云 API 管理密钥、某软件代理商的 Square 生产令牌、某病历类应用云数据库的所有者密码。Apiiro 没有逐一验证凭据是否仍有效，但其中一家被通知的组织确认，自己的密钥当时确实还能用。

四、为什么扫描器漏

对 1,122 份含密钥的文件，gitleaks 命中 564、TruffleHog 命中 643，两个都没抓到 215 份。原因不难理解：这类工具按「已知前缀 + 高熵字符串」识别密钥，而 PGPASSWORD= 后面的明文密码、sshpass -p 后面的口令、mysql -p 后面的密码、curl 请求头里的 Authorization，看起来都像普通文本。

  • 结论一：开了密钥扫描不等于安全，扫描器擅长认「格式」，不擅长认「语义」。
  • 结论二：真正能兜底的是流程——凭据不进命令行、不进 agent 的配置文件、不进会话记录。

五、内网 agent 的三条规矩

  • 先轮换，再清理：删文件不删历史，fork 也还在；凡进过这个文件的凭据，一律当已泄露处理。
  • 把 agent 的「副产物」纳入敏感资产清单：配置文件、会话记录、部署笔记、任务交接说明都在泄露范围内，不只是代码与文档。
  • 授权规则按前缀最小化：能自动模式就别堆 allow 列表；必须记规则时用前缀匹配而不是命令原文，让密码没有落盘的机会。

这三条对云端工具与内网部署同样成立。差别只在于：内网部署时，泄露的落点是自己的仓库与自己的机器——发现问题的时间更早，但影响面也更集中，往往一次就是一个机房的口令。

agent 的配置文件算不算敏感资产？算

按两套口径记，按轮换处置（2026-11-11）

  • Apiiro：103,617 个仓库含该文件 104,185 份，1,122 份含真实密钥；合并历史与会话记录后 2,539 个凭据、63 家组织。
  • GitGuardian：23,276 个仓库、31,088 个不同密钥，17% 在检出时仍有效——这个数才是应该被轮换的规模。
  • 常规扫描器有 215 份完全没抓到：明文密码不像密钥，格式识别管不了语义泄漏。
  • 处置顺序：轮换凭据 → 清历史与 fork → 把 agent 副产物纳入资产清单 → 授权规则按前缀最小化。
