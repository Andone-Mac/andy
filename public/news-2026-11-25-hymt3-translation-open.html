中国混元开源翻译模型 HyMT3：102 种语言、误译样本降 43%，最小 1.8B 端侧可跑

11 月 24 日，腾讯混元开源第三代翻译模型 HyMT3：支持语种从 38 种扩到 102 种，真实场景误译样本比例降 43%、漏译增译降 74%，提供 1.8B/7B/30B-A3B 三种尺寸与 FP8、GGUF 量化版。30B-A3B 运行时仅激活 3B 参数，官方口径在非思考模式模型中综合效果最佳；浏览器插件已登陆 Chrome 与 Edge，支持本地模型安装与离线使用。对跨境业务与文档翻译场景，这是「翻译能力私有化」的一个新选项。

一、开源了什么

11 月 24 日，腾讯混元在 Hugging Face 与魔搭 ModelScope 开源 Hy-MT3-1.8B / Hy-MT3-7B / Hy-MT3-30B-A3B 三个尺寸，并在 GitHub 开源翻译自动评估方案 TransRubric；技术报告见 arXiv 2611.27673。这是混元翻译模型家族第三代（前两代为 Hy-MT2、HY-MT1.5）。

  • 三种尺寸：1.8B、7B、30B-A3B（MoE，运行仅激活 3B 参数），官方定位覆盖 PC、手机、智能设备等端侧场景。
  • 量化齐全：每个尺寸都有 FP8 与 GGUF（llama.cpp）版本，CPU 与低显存设备有现成入口。
  • 可微调：官方提供全量微调与 LoRA 流程，支持 DeepSpeed ZeRO 与 LLaMA-Factory 集成——术语库、行业文风可以训进去。

二、质量提升（官方 README 口径）

指标HyMT3 相对 Hy-MT2
支持语种38 → 102（38 种已有 + 64 种新增，含低资源语种）
误译样本比例降低 43%
漏译 / 增译比例降低 74%
指令遵循类错误减少 40%
30B-A3B 每样本推理计算量不到 1 TFLOP

厂商横向口径（均为官方 README 表述，非本刊独立验证）：30B-A3B 在所有非思考模式模型中综合效果最佳，超过 Qwen3.8-Max、Kimi-K3.1-Pro、DeepSeek-V4.1-Flash 等旗舰，接近 GPT-6.1-Sol、Gemini-4-Argon 等闭源思考模型，并超过推理计算量是其 30 倍以上的模型；1.8B 在通用翻译上超过讯飞翻译、微软翻译、Qwen-MT-Flash 等商业 API。

三、两个产业场景与开源评估

  • 游戏本地化：与王者荣耀团队共建垂类数据与评测体系，官方称在脱靶率、占位符错误、富文本错误、术语错误等核心指标上持平或优于 Gemini 3.1 Pro（厂商口径）；游戏翻译工具链 TiMiHOKGameTranslator 已开源，可接入研发流水线。
  • 图片翻译：针对 OCR 级联场景强化上下文理解与纠错，官方称 VISTA-Bench 同尺寸最强（厂商口径）。
  • TransRubric 评估方案开源：WMT26 自动评估赛道 Task 2 句子级 PDP 0.744、Avg Corr 0.832 均为最高；与 10 位专业标注员对比，10 次打分的单条标准差 3.31 分（人工 15.57 分），成对准确率 59.91% 高于其中 7 位。

四、端侧与离线：翻译不必上云

据 c114 通信网 11 月 24 日报道，混元翻译浏览器插件已登陆 Chrome 与 Edge，支持本地模型安装与离线使用。配合官方 GGUF 版本，翻译可以完全跑在本地硬件上——译文与原文都不必经过云端 API。

  • 1.8B GGUF 版可走 llama.cpp 在 CPU 上推理，硬件门槛低。
  • 本地部署意味着待翻译内容留在本机或内网，涉外文档、合同、客服记录等敏感文本多一条不出域的路。
  • 跨境电商、游戏出海、涉外政务文档等场景，可按「质量优先选 30B-A3B、成本优先选 1.8B/7B」分档评估。

机悟视角：翻译能力私有化

小模型 + 离线插件，数据不出域的低门槛入口。

  • 涉外文档翻译是政企高频需求，本地部署避免敏感内容上传云端。
  • 1.8B/7B 硬件门槛低；30B-A3B 仅激活 3B，是质量优先档的候选。
  • 102 语种覆盖多数出海目的地，低资源语种与少数民族语言支持是加分项。
  • 机悟可协助：翻译负载评估 + 端侧/内网部署方案 + 术语库微调集成。
