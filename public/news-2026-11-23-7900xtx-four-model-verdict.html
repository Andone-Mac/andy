一张 7900 XTX 该跑哪个本地模型？11 月 21 日四档 228 题实测：27B 满分、74B 丢 4 分

11 月 21 日，同一张 AMD RX 7900 XTX 24GB 外接显卡，四个本地模型同卷 57 题、228 条回答：27B 的 V3.1 与 Arete 均 57/57 满分，74B 大模型 53/57，单题中位耗时还比 Arete 慢约 42.0%。本文不摆公式，读完第三节就能判断自己的机器该跑哪一档；判分协议与五道错题见同日证据版。

一张表：四档谁满分、谁丢分

考卷分两层：45 道基础题（数学、知识、逻辑、代码、指令遵循、中文、结构化输出）加 12 道困难题（竞赛数学、进阶代码、硬逻辑、古文、长上下文检索），全部程序判分——对就是对，错就是错，没有人工印象分。四档成绩如下：

最反直觉的是最后一行：74B 的模型，参数接近 27B 的三倍，不但没拿满分，还最慢。原因在下面三句话里。

三句话解释为什么

  • 第一句：它答得更长。57 题下来 74B 档共输出 32,101 tokens，约为 Arete 档（13,504）的 2.4 倍——每题字多，自然慢，困难题单题中位耗时 17.4 秒对 12.9 秒。
  • 第二句：丢分集中在中文与古文（4/7）和代码边界，数学、知识、逻辑全对。这一档用极限量化（IQ2_XXS，权重 20.51 GiB，见本站 11 月 13 日实测）把 74B 塞进 24G 卡；丢分形态与量化档一致，但本次没有做量化消融，不下因果断言。
  • 第三句：三个 27B 是同一底模的不同微调。满分的是官方 V3.1 与去审查的 Arete；去审查的 Huihui 丢了一题，也丢在代码边界——去审查微调不是零代价，但这次只差一题。

Agent 干活：关掉「先想再答」，省一半时间不掉质量

上面能力卷不开投机解码；这一节是另一套 agent 负载：9 道工具调用与严格 JSON 题，外加一轮 8 轮长对话记忆测试，MTP 投机解码开启。结果：四种配置的工具与 JSON 题全部 9/9 全对，长对话记忆也全部正确（项目代号与预算原样复述）。

  • V3.1 思考开：平均每题 3.6 秒、输出 121.9 tokens；思考关：2.0 秒、41.8 tokens——时间省 43.9%，tokens 省 65.7%，正确率不变。
  • Arete 思考开：4.5 秒、161.9 tokens；关：2.0 秒、41.8 tokens——时间省 56.4%，tokens 省 74.2%。
  • 说人话：在这套工具考卷上，「先想再答」没有换来正确率，只换来更长的回答。追求响应速度的 agent 场景可以默认关思考；但这是这套考卷的结论，不是所有任务的结论。

口径说明：长对话记忆一项脚本未传思考开关，两组数字是同一默认配置下的两次采样（每轮均值 2.8–2.9 秒）；上面的开关对比只适用于 9 道工具与 JSON 题。

现在怎么选

  • 手里是 24G 卡：27B UD-Q4_K_XL 当主力。V3.1 与 Arete 都满分，权重分别 16.45 GiB 与 15.66 GiB，给上下文留足余量。
  • 经常喂长文档：选 Arete。上下文上限 218,000 tokens 为四档最大，112,162 字符的长文检索题它 42.8 秒答完，四档最快。
  • 74B 档数学、知识、逻辑全对，丢在中文古文与代码边界；业务重古文就等更高质量量化档，别为参数量付钱。
  • 思考开关：工具与 JSON 场景关掉（省 65.7%–74.2% tokens）；需要深度推理的场景开着，并用自己的业务题单独验证。

三个提醒

  • 满分不等于全能。这是 57 题的程序判分考卷，不测开放创作、多模态与你的真实业务；签约前用自己的题复测。
  • 上下文不是免费的。163,840 / 218,000 tokens 的上限是压缩 KV 缓存口径；112,162 字符的长提示词，答一道检索题要 42.8–53.9 秒——文档越长，越要给预填充留时间。
  • 两套负载口径不能互推：能力卷不开投机解码，agent 卷开；全程单卡独占。速度不外推到共享或多卡环境。
