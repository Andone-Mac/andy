中国腾讯开源 WeMM-Video 全模态模型：四档 2B 到 35B，Apache 2.0 许可

11 月 20 日，腾讯 WeMM 团队把 WeMM-Video 全模态模型家族放上 GitHub 与 Hugging Face（仓库 Tencent/WeMM-Video，技术报告 arXiv 2611.26409）。这不是又一个「看图说话」模型：文本、图像、音频、视频都能进，文本出，看视频时可以直接用原声轨，官方称预训练用了约 1.2 万亿多模态 token。对政企私有化更关键的是许可——模型集合自 2026 年 11 月 20 日起采用 Apache 2.0（LICENSE 文件，第三方组件除外）。本站 11 月 20 日刚讲过 混元 Hy4 旗舰开源与许可第 10 条收入红线，本篇把 WeMM-Video 的档位、基准与部署门槛摊开对照。

一、四档规格与「全模态」到底指什么

README 口径：家族含 2B、4B、9B 三个稠密模型与一个 35B-A3B 混合专家（MoE）模型；输入模态为文本、图像、音频、视频，输出为文本；每档提供 Instruct 与 Thinking 两种模式；视频理解可直接使用原声轨，音画一起进模型。预训练为渐进式预训练 + 多阶段后训练，总量约 1.2 万亿多模态 token（README 表述）。官方服务示例限定单请求最多 4 图、2 视频、2 音频。

二、基准怎么读：开源阵营里领先，但别越级对比

技术报告 Table 0 把 35B-A3B 与 Gemini-3.0-Flash、Seed2.0-Mini-0428、Qwen3.5-Omni-Flash 同表对比：Video-MME（含音频）Instruct 84.2、Thinking 86.4，低于 Gemini-3.0-Flash 的 88.6，高于 Seed2.0-Mini 的 83.6 与 Qwen3.5-Omni-Flash 的 79.3；Video-MME-v2 Thinking 54.9，对 Gemini 的 63.2 仍有差距；AVHBench Judgement 80.3/80.0 则高于 Gemini 的 78.5。README 自称「开源 SOTA」，应限定为开源模型阵营内领先；与闭源旗舰互有胜负，多数视频指标仍落后 Gemini-3.0-Flash——引用时把阵营和版本号都带上。

三、私有化部署门槛：量化档位、运行时与许可三件套

官方提供 BF16、FP8 Block128、AWQ W4A16、GGUF Q4_K_M、NVFP4 W4A16 多种量化档位；运行时支持 Transformers、patched vLLM（官方镜像 wemm-video:vllm-0.18.0-cu129）、patched SGLang（0.5.16）与原生 GGUF。参考环境 Python 3.12、CUDA 12.9、torch 2.10.0、transformers 5.2.0；官方服务示例参数 --max-model-len 8192、视频采样 fps 2、4–16 帧。显存需求 README 未给统一数字，按量化档位与 HF 模型卡实测为准；GGUF Q4_K_M 档为本地与边缘部署留了口子（本刊按公开档位归纳，未实测）。

  • 许可三件套一起读：LICENSE（Apache 2.0，模型集合自 2026-11-20）、THIRD_PARTY_NOTICES.md（第三方组件除外）、examples/README.md 的 media-credits（示例素材版权）；各 checkpoint 许可以 HF 模型卡为准。
  • 与混元 Hy4 的 Tencent Hy License（含第 10 条收入红线）不同，Apache 2.0 对商用与二次分发更宽松——但「宽松」不等于「无义务」，署名与声明条款仍要履行。

机悟建议：全模态私有化，先核许可再核显存

Apache 2.0 是集合口径，逐 checkpoint 以模型卡为准

  • 许可三件套（LICENSE、第三方声明、示例素材版权）一起核，各 checkpoint 以 HF 模型卡为准。
  • 档位按场景选：边缘/轻量用 2B–9B，音画联合理解的重场景再上 35B-A3B。
  • 视频带原声轨的场景优先 Thinking 档，基准差距主要在这一档拉开。
  • 内网显存、量化档位与许可义务一起评估，机悟可提供约 40 分钟的选型评估。
